### 支持的版本

### 报告漏洞

如果你发现安全漏洞，**请不要**在公开的 Issue 中报告。

请通过以下方式私下报告：

1. **GitHub 私密安全报告**（推荐）
   - 进入仓库的 Security 标签
   - 点击 "Report a vulnerability"
   - 填写漏洞详情

2. **邮件联系**
   - 发送邮件至项目维护者（在 GitHub 个人资料中查找联系方式）
   - 邮件标题请注明：`[SECURITY] OpenBene 安全漏洞报告`

### 报告内容

请在报告中包含：

- 漏洞的详细描述
- 复现步骤
- 受影响的版本
- 可能的影响范围
- 如有可能，提供修复建议

### 响应流程

1. 我们会在 **48 小时内**确认收到报告
2. 我们会在 **7 天内**提供初步评估
3. 我们会与报告者协调修复时间表
4. 修复发布后，我们会公开致谢（除非报告者要求匿名）

### 安全更新

安全更新会通过以下渠道发布：

- GitHub Releases（带有安全标签）
- CHANGELOG.md 中标注

## English

### Supported Versions

| Version | Supported |
| ------- | --------- |
| 2.x     | ✅ Yes     |
| 1.x     | ❌ No      |

### Reporting a Vulnerability

If you discover a security vulnerability, **please do not** report it in a public Issue.

Please report it privately through one of the following methods:

1. **GitHub Private Security Reporting** (Recommended)
   - Go to the Security tab of this repository
   - Click "Report a vulnerability"
   - Fill in the vulnerability details

2. **Email Contact**
   - Send an email to the project maintainer (find contact info in GitHub profile)
   - Use subject line: `[SECURITY] OpenBene Security Vulnerability Report`

### What to Include

Please include in your report:

- Detailed description of the vulnerability
- Steps to reproduce
- Affected versions
- Potential impact
- If possible, suggested fixes

### Response Process

1. We will acknowledge receipt within **48 hours**
2. We will provide initial assessment within **7 days**
3. We will coordinate a fix timeline with the reporter
4. After the fix is released, we will publicly credit the reporter (unless anonymity is requested)

### Security Updates

Security updates will be announced through:

- GitHub Releases (with security label)
- Noted in CHANGELOG.md
