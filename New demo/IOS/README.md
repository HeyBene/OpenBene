# iOS 本地采集与锚点航线

Swift + ARKit + CoreBluetooth。地图由用户现场采集，以 JSON 文件保存在本机，不加载预设房间或预设地图。采集与执行共享同一套锚点坐标系。

## 构建

```sh
brew install xcodegen
cd IOS
swift test
xcodegen generate
open OpenBotAnchorNav.xcodeproj
```

在 Xcode 中选择自己的签名 Team，连接 iPhone 后运行。Bundle ID 为 `com.openbene.anchornav`，部署目标 iOS 15。每次重新生成工程后检查签名 Team。

`Info.plist` 已包含相机和蓝牙用途说明，以及“文件”App 访问配置。它由仓库维护，XcodeGen 仅通过 `INFOPLIST_FILE` 引用；不要用空的 `info.properties` 覆盖它。

## 采集自己的地图

1. 首页点击 **采集新地图**，选择一张定位图片。默认完整图片宽度为 **20 cm**；可以分享/打印图片，如果改变打印宽度，在界面填写实际宽度。
2. 将完整的图片平放并固定在地面。它用于建立坐标系，没有预设的房间位置。采集和以后应用地图时，图片的位置、尺寸、方向需要保持不变。
3. 点击 **开始采集**，启动时显示准备进度；用相机对准完整标记图，等到“锚点已固定”。当前定位使用 ARKit 图像锚点，需要完整图片，而不是只裁出中间二维码。首次识别后可以离开图片，继续使用相机位姿采集。
4. 将手机固定到实际使用的支架上，镜头斜向前下方，点击 **确认支架处出发位置**，开始记录紫色轨迹。无需移到图片中心上方，也没有指定扫描高度。图片只定义地图坐标原点，确认时的支架位置另存为路线出发位置；手持扫描、安装支架期间的移动不会进入路线。沿实际可行路线到起点，点击 **采集起点**，再采集后续节点。
5. 移到第一个节点，面向希望到达后采用的方向，填写名称并点击 **添加节点与朝向**。
6. 按顺序采集其余节点。优先保持手机在支架上、手推底盘采集；如果取下手持，应保持与支架一致的镜头朝向和俯仰，记录期望的车头朝向。画面显示人工节点及朝向箭头，点错可 **撤销**。
7. 点击 **保存地图**，输入名称。后台逐段生成并校验带状空间内的子节点路线，再将原始轨迹、人工节点和生成路线一起保存到本机。定位中断导致两个人工节点之间缺少连续轨迹时会拒绝保存，不补直线。

采集页紫色线是手机相机运动的**地面二维投影**。按 ARKit 帧时间以 **30 Hz** 目标频率记录位置、朝向、时间和连续性，不再要求移动4cm；相机帧率不足时不会虚构采样。紫色箭头也按最高30Hz更新，文字状态约10Hz刷新。跟踪丢失或超过0.6秒没有连续帧时断段；不跨缺失轨迹补线。显示窗口最多5000点，但保存的完整历史不会随窗口裁剪，最多54000点（约30分钟，人工节点可额外钉住所用相机帧）。到上限明确提示并停止追加，不能继续添加节点；已有节点仍可保存。撤销普通节点保留实际轨迹；撤销起点清空轨迹，并需重新确认支架处出发位置。

保存时，以各相邻人工节点对应的实测轨迹为中心，左右各15cm形成总宽30cm的带状空间（折线线段的半径15cm胶囊体并集，转角圆接）。先用5mm误差简化冗余候选点；过长的一段最多逐步放宽到30mm，最多512候选点，仍超限时提示增加人工节点分段。候选子节点都是轨迹实测点。在按采集顺序构成的可见性图上，动态规划优先取直线段数最少的路线，同段数取更短路线。这里的最少针对选定的有序候选点，并非任意连续位置的全局最优。

候选直线必须**整段**被带状空间覆盖，以解析的线段/胶囊体相交区间并集判定，不只检查端点或稀疏采样。规划时减去简化误差并另留4cm控制余量，保证简化后被接受的线段仍在原始15cm半宽内。每段分别生成，人工节点不会被跨过或改变朝向。原始轨迹只用于保存、规划和采集显示，**导航地图与AR场景只显示生成的子节点折线**。

位置与朝向以手机相机为参考。执行时需与采集保持相同安装位置和朝向。该带状空间约束手机位置和计划中心线，不包含底盘宽度、转动扫掠体积或障碍物检测；AR漂移和真实底盘惯性仍需现场测试。旧v1地图保留并可预览，但因缺少实测轨迹不能执行新版带状路线，需要重新采集。此次只升级iOS，Android尚未支持v2地图。节点位置在直行结束时确认，停车2秒后进入朝向调整。该阶段只判断角度，不因相机绕底盘转轴的位移而重新找点，不要求测量支架偏移；跟踪、蓝牙和碰撞保护仍保留；带状空间连线在开始直行前按实际位姿重新检查，超出则停车，不因此再次原地找点。3cm是转向前的到点判定，不是转向后相机仍处于同一3cm圆内的保证。

## 应用航线与底盘执行

1. 首页选择已保存地图。可以先保持 **通过蓝牙驱动 OpenBot** 关闭，此时只显示航线和模拟轮速，不向真实底盘发送命令。
2. 需要驱动时，打开该开关，点击 **搜索底盘** 并选中自己的 OpenBot。
3. 点击 **应用地图并显示航线**。重新识别同一张定位图片，连续稳定约0.5秒后锁定。随后保持手机在支架上，无需为了启动改变俯仰。定位可用、底盘已连接、当前位置在原首段的保守带状范围内且距离原出发位置不超过 **75 cm** 时可开始。启动会从真实当前位置重新生成首段接入折线，保留人工节点顺序，并同步更新AR和俯视图。当前位置在原带外时，应移动整台车到带内，不会用未采集区域补一条连接线。
4. 点击 **开始执行**。按采集顺序经过锚点处、人工起点、各人工节点之间生成的子节点：
   - 原地转向当前航线方向。保持所设PWM，用40/100/200毫秒短脉冲按角度大小推进，脉冲间至少停车250毫秒；稳定确认350毫秒后，再停车等待 **2 秒**准备直行；
   - 直行到节点附近，小角度偏差用左右轮差速修正，方向偏差超过 6° 时停车并原地转向；
   - 自动子节点到点后停车等待 **2 秒**，再转向下一段，不恢复采集手机朝向；
   - 人工节点到点停车等待 **2 秒**，再原地转到该节点记录的朝向；
   - 停车等待 **2 秒**，再转向下一段航线；最后一个节点的位置与朝向完成后立即停车结束。
5. **停车**立即停止本次执行；**退出**停止并关闭蓝牙链路。停止后重新执行，需要移回所选路线的出发处。

## 从节点返程至锚点旁出发位姿

去程到点后保持导航页和同一个AR会话，停车后选择 **返程至锚点**，选择车所在的人工节点，再点 **开始返程**。通常自动选用最近已到达的人工节点，也可以选择中间节点或人工起点。界面预览返程路线。车应位于所选节点75cm内且在返回上一节点的已采集保守带内；不从任意带外位置生成直达连线。

返程倒序使用该节点之前的已采集子节点和人工节点，保留墙角；首段可从实际当前位置在同一带内接入，不改写保存地图。执行仍是先转向、停车2秒、向前直行、到点调整人工节点记录朝向，不发送倒车指令，沿用已保存的直行/左右转PWM与定位/带状空间等停车条件。终点是 **确认支架处出发位置** 时保存的位置及朝向，不是强制车驶到纸张中心。必须有完整采集的锚点旁出发段（`anchorStart`）；缺少该段的旧地图需要重新采集，不能假设未走过区域可通行。

返程最后一段、VIO估计距原出发位置35cm内时，持续查看完整定位图片，转向期间也检查。一旦看到图片先停车，用后续至少12帧且持续0.5秒的稳定观测重新建立图片坐标，再计算当前相机到原出发位置和朝向的残差。坐标关系为 `T_map_camera = inverse(T_AR_marker_fresh) × T_AR_camera`；保存的出发位姿不变，也不会把当前车位直接赋成目标位姿。

图片重对齐后，残差在30cm内才允许末端物理微调：停车2秒、对准目标连线、向前直行、再调整到保存朝向。此阶段仅限原出发位置周围半径30cm的局部区域，需要该区域实际可通行；它不是障碍地图或避障规划。最终转向后必须重新识别图片，位置误差≤5cm、朝向误差≤5°才报告完成。未看到图片时围绕保存朝向依次偏转−25°、+25°、回零寻找，各段间停车2秒；最多3轮微调、总计90秒，找不到稳定图片、偏差过大或残差不收敛均明确停车。转向仍沿用短脉冲制动。不要求测量相机相对底盘中心的偏移，但未知支架偏心可能影响收敛，不能保证底盘中心达到5cm精度。普通去程和返程中途仍不重定位；退出、后台或AR会话重建后不能直接从远处恢复定位。

新带状路线的节点位置容差 **3 cm**（避免旧30cm容差在墙角提前转向）、节点朝向容差 **5°**，直行前航线方向容差 **3°**。参数位于 `WaypointConfig`；v2路线采用有制动的转向控制。方向误差变号时先停车至少2秒再反向，避免高频左右切换；标称角度容差的稳定保持阶段有额外2°滞回。单次转向超过45秒、8秒没有有效角度进展、有效累计转动超过270°或出现明显朝向跳变时停车。累计转动按相对上次计数点的≥3°净变化计数，不累加每帧细小朝向抖动；过冲或扰动后重新接近当前目标也算进展，不要求每次都超过本轮历史最小误差。跨转向/直行阶段30秒未向当前节点接近也会停车，防止短段反复切换阶段。短脉冲有独立到期停车定时，不依赖下一帧相机回调。现场尚未标定。每帧检查当前位置到目标子节点的直线是否仍在保守带内，超出后停车并要求回起点重启。首次识别后地图坐标固定；普通行驶中再次看到图片不会重定位，仅返程末端启用上述明确的图片归位阶段。v2路线跟踪暂时受限或相机帧中断时保留当前节点并停车，恢复位姿与停车前连续、在0.5秒窗口内稳定后，停车2秒再自动继续。窗口内位置变化≤3cm、朝向变化≤3°且至少6帧，不能用缓慢漂移伪装稳定。参考停车前的连续性要求为位置≤30cm、朝向≤45°；15秒未恢复、同一节点已恢复3次仍反复中断则结束。朝向突跳先进入恢复等待，8秒无进展、45秒转向不收敛等机械/控制失败仍结束执行，不无限重置。恢复不跳过当前子节点，不改地图坐标，准备直行时仍检查整段带状约束。切后台或 AR 会话中断后需退出页面重新进入。界面不实现自动避障或绕行。

导航默认直行、左转、右转 PWM 均为 **160**，现在可在 **PWM 调节与测试** 面板分别调整并保存。以默认值为例：原地转向左右 PWM 为 **−160 / +160** 或相反，直行基础 PWM 为 **160 / 160**，接近节点不降低基础输出；差速微调时单轮约 **133～187**，停车为 **0 / 0**。各动作切换停车等待 **2 秒**，包括偏航后从直行切回原地转向；同次转向反向纠偏也先停车2秒。等待期间定位或蓝牙异常、手动停车均取消后续动作；等待结束后按最新位姿决定动作。等待采用计时状态，不阻塞相机和界面。参数需要按现场情况测试，不代表已完成底盘标定。

## 调整 PWM 与短时测试

1. 在首页启用蓝牙、搜索并选中自己的底盘，再点 **PWM 调节与测试**。不需要地图或识别二维码；没有选择底盘时仍可设置参数，但测试按钮禁用。
2. 分别调整 **直行基础 PWM**、**原地左转 PWM**、**原地右转 PWM**，范围 **0～255**。滑块可快速调整，步进器以 1 为单位微调，默认均为 160。改变数值会先停止当前测试。
3. 先架空底盘，再点 **前进 1 秒**、**左转 1 秒**、**右转 1 秒**。每次最多发送 1 秒的测试指令，随后自动停车；也可随时点 **停车**。面板显示电池电压（有遥测时）、最近提交的控车帧及连接状态。退出面板、切后台或失去连接都会停止测试；不会自动再次启动。
4. 调整满意后点 **保存并应用**，参数保存在本机，重启 App 和更新安装仍保留。只修改滑块不会覆盖已保存值。**恢复 160 / 160 / 160** 先恢复面板数值，再保存才会生效。从旧版本升级时，原转向值会同时沿用到左转、右转，直行值保持原样。
5. 导航页可点 **调节 PWM**，会先停车；保存后需要回到采集起点，手动重新开始。此入口只设置参数；独立短时测试位于首页面板。

直行设置的是基础输出，航线微调时两轮会略有不同，编码仍限制在 -255～255。左转用左转设置 L，发送 c-L,L；右转用右转设置 R，发送 cR,-R。每次转向的两轮仍使用相同绝对值、相反方向；这里分别校准左转和右转，不是单独设置左右轮。短时测试和导航中的初始转向、纠偏转向、到点朝向调整都使用对应方向的值。航线导航仍保留动作之间停车2秒；视觉跟随使用距离停车和急转弯优先对准，其他制动实验仍可独立开关。航线导航、视觉跟随和跟随采集共享这三项已保存参数。短时测试使用面板当前值，导航使用已保存值。

## 视觉跟随与近人停车

导航页的 **跟随** 与采集页共用`PersonFollowDriver` / `FollowExecutor`。iOS16及以上使用随App离线附带的Ultralytics **YOLO11n CoreML**，iOS15使用Apple模型目录的 **YOLOv3 Tiny**；仅选择COCO `person` 类，通过Vision执行CoreML模型，最高每秒15次尝试检测，后台串行推理、复用AR相机帧，不另开相机。模型来源、哈希和许可见`Resources/Models/README.md`。不再使用`VNDetectHumanRectanglesRequest`上半身检测。模型输出是人体框，包含部位由实际可见内容决定，不保证仅见腿时的检测能力。

已移除按人体框大小标定的 **设定距离**，不再从框高、框宽或框顶位置推断远近。支持LiDAR的设备使用同帧ARKit `sceneDepth` 测量人体区域的水平距离。**5秒后跟随** 的倒计时仅供人站到相机前，结束时有新鲜有效检测才启动；默认一帧即可。初次选择最大框，后续按重叠与中心距离匹配，超过0.6秒未匹配才重新选取；不是身份识别，多人交叉仍可能换人。仅对水平中心作0.10秒时间常数平滑，并估计水平移动趋势，用于提前判断侧向出画风险；跟随距离始终取几何匹配到的同一人体框对应测量。启动失败取消本次动作，之后出现人不会突然启动。

**接近人时停车默认开启**，直接在跟随主卡片显示开关与0.5～2米距离滑块；开关和米数会本机保存，采集与导航共用。跟随不是自动启动，仍需手动点击 **5秒后跟随**。点 **更多** 可逐项测试其他默认关闭的条件：置信度≥0.6、必须单人、连续3帧、四边1.5%空隙、目标跳变、0.35秒严格过期、转向100ms输出/250ms制动、左右反向前2秒停车。**关闭其他测试门槛**保留当前近人停车设置。改动任何选项先停车、清除旧检测，需返回后手动重新开始。关闭单人条件时仍保持几何匹配，但不能保证多人场景中的身份一致性。

小幅偏差仍采用OpenBot式连续前进差速，转向变化限幅为每秒2；水平移动趋势作0.10秒短时前馈。目标当前偏离画面中心超过22%，或超过18%且正快速朝边缘移动、预测0.12秒后偏离超过24%时，优先停止前进80ms，再按该方向已保存的转向PWM原地对准（180ms输出/至少120ms制动）。目标回到中心±10%即停车200ms，之后再前进；若越过中心需反向，先停300ms。接近人且保持距离时仍只允许原有120ms/400ms短时原地对准。普通小幅左右变化不会进入这种大角度转向，避免重回小偏差即左右摇摆。左右转PWM独立保留，不重置设置。这是目标仍可见时的取景与转向控制，不能保证人快速消失在墙后时还能继续视觉追踪。无目标立即零输出，超过0.6秒也保留本次跟随授权、停车等待，目标重新有效可见后自动继续；开启严格过期实验才收紧到0.35秒，同样不会盲转寻找看不见的人。单人/四边/跳变等可选门槛触发时也先暂停，条件恢复后继续。AR短暂受限时停车，恢复正常0.5秒后再按最新检测继续，最长等待15秒。BLE断开、碰撞事件、切后台、会话结束、改配置/PWM和手动停车仍取消跟随，不自动启动。其他测试条件关闭时仍保留上述失效停车及底盘通信心跳。

**近人停车**：现在根据实测距离，移除了“框顶碰上缘”判定和红色停车线。默认距手机水平距离≤1米禁止前进；>1.2米且至少3次新鲜测量、持续0.4秒后恢复前进。阈值可调0.5～2米，释放距离固定加0.2米；变更设置先停车，需要手动重新开始。旧版图像停车线与开关使用不同偏好键，不迁移为米数；距离法首次使用默认开启/1米。

测量复用ARKit世界跟踪的LiDAR深度图，在YOLO人体框内部中央区域采样，过滤低置信度、无效深度、有效样本不足与人体/背景混杂的区域。用相机内参反投影，并以ARKit重力对齐的相机旋转计算水平距离，消除支架俯仰对深度的影响；不要求人的头和脚完整入镜。距离属于匹配到的人，不会随另一更大框的读数变化。界面显示“LiDAR水平距离约…米”；不支持LiDAR、测量无效或过期时明确显示距离未知并禁止前进，不静默回退到图像上边界法。该距离以手机为参考，未包含底盘外形或机械制动距离，也没有增加普通导航避障或绕行。没有主动搜索完全看不见的人。

主卡片优先显示开始/停车、近人停车开关和阈值；**检测与控车详情**默认折叠，展开显示原始/筛选后框数、耗时/帧龄、已开条件、阻塞原因、PWM、计算c帧和最近蓝牙帧。绿色人体框显示在相机画面，距离显示在卡片中。日志记录在App本地`Documents/Diagnostics/follow.jsonl`（约2MB轮转，另保留上一份），不保存照片或视频。10月19日用户复现日志显示手机保存直行135、左转172、右转172；此次保留这些设置，不强制重置160。控车帧已提交不代表电机实际转动。

## 跟随采集

1. 首页启用蓝牙、选中底盘，再进入 **采集新地图**。无底盘仍可手动采集，跟随禁用。
2. 识别并固定图片坐标，将手机固定在支架上、保证目标进入相机可见范围，点 **确认支架处出发位置**。保持支架姿态，VIO继续以30Hz记录手机实际轨迹。
3. 采集页控制面板最上方为 **跟随采集**，并非自动开始。先确认支架出发位置、等待底盘连接后，架空点击 **5秒后跟随**。准备时间内站到相机前，先不启动车辆，观察人体距离能否随走近/走远变化，再架空验证前进/转向、手动停车与到所设距离后禁止前进。不需要设定距离。
4. **接近人时停车**默认开启，滑块可直接调整0.5～2米停车距离，默认1米、1.2米后稳定再继续；每次调整先停车，需要重新开始跟随。其他条件在 **更多** 内逐项测试；声呐未安装、w轮速仅显示的约束不变。
5. 现场条件验证后再落地跟随采集。点 **采集起点** / **添加节点与朝向** 会先停车，若刚运动则等待2秒，随后记录最新停稳位姿；需手动重新跟随。此2秒记录间隔不属于已关闭的跟随制动条件。
6. 保存、撤销、改PWM、退出、后台与容量上限等原有采集停车行为保留。保存的原轨迹、30cm带状规划和去程/返程不变。控制面板高度受屏幕约束并可滚动，跟随入口置顶，诊断默认折叠；出现“未选择底盘”时需先返回首页开启蓝牙、选中底盘，再进入采集。

## 相机视野

采集和导航以完整相机画幅适配屏幕显示，允许上下留白，不把4:3传感器画面放大裁成整块竖屏。人体框叠加位于同一相机视口；检测筛选、转向坐标和深度区域与该视口一致，不再因为手机屏幕更长而丢掉左右侧本来已识别到的人。VIO、锚点图片和地图坐标不变。

已在当前iPhone12Pro读取ARKit `supportedVideoFormats`：物理后摄有普通广角与超广角，但世界跟踪格式全部来自普通广角，没有可直接选择的超广角格式。当前修复没有切成0.5×镜头，也没有另开相机抢占AR会话。Debug启动时将只读能力信息写入`Documents/Diagnostics/camera.jsonl`；硬件默认格式的FOV数值不代表AR会话实际投影。

## 本地文件

- 每张地图为 `Documents/Maps/<UUID>.json`，v2保存锚点规格、支架处确认的执行起始位姿、人工起点和节点、完整30Hz轨迹、节点对应采样索引、生成路线及校验参数。文件上限32MB。
- 首页可 **导出地图 JSON**、**删除此地图**。地图现场采集，不提供地图导入入口。
- 可在“文件”App 的 **我的 iPhone → Anchor Nav → Maps** 中备份或管理文件，回到 App 后会重新加载。
- 只支持这版 App 生成的地图格式；不加载旧预设 `demo_floor.json`。损坏或不兼容的文件保留原样，并报告加载问题。
- 卸载 App 会删除应用内文件，需要保留的地图请先导出。

## 代码与验证

- `RecordedMap` / `MapCapture`：记录起点、节点与朝向，保存v2轨迹地图；兼容读取v1。
- `RecordedMapStore`：本机文件保存、加载、导出与删除。
- `AnchorARSession` / `FixedAnchorFrame`：首次识别固定图片锚点，持续使用 ARKit 相机位姿，统一采集与执行坐标。
- `WaypointExecutor` / `SettledTurnController`：转向航线、直行、节点朝向调整、顺序推进与短脉冲制动。
- `StableAnchorAlignment`：初始图片多帧稳定确认；朝地过陡时不输出用于控车的车头朝向。
- `RouteEntryPlanner`：从当前真实位置在原首段带内生成临时接入方案，不改写保存的地图。
- `CaptureTrajectory` / `PhoneTrajectoryDrawing`：采集时手机位姿的完整归档与有界显示采样、跟踪断段、紫色轨迹与当前位置箭头；共用固定锚点坐标，不依赖 ROS2 或额外原始 IMU 积分。
- `TrajectoryRoutePlanner` / `TrajectoryCorridor` / `CapturedRoute`：带状空间整线段校验、有序候选点上的最少折线、持久方案校验和执行路径。
- 原 `RouteExecutor`、路由器、锚点数学与跟随算法保留在内核中；旧示例地图只作为算法测试夹具存在，不打包为 App 的默认地图。
